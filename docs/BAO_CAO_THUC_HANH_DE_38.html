CHƯƠNG 1: TỔNG QUAN ĐỀ TÀI VÀ TIÊU CHÍ ĐÁNH GIÁ

1.1. Đặt vấn đề và Mục tiêu nghiên cứu

Quản lý tài chính cá nhân và hộ gia đình là nhu cầu thiết yếu trong đời sống hiện đại. Mục tiêu của đề tài số 38 là xây dựng và triển khai hoàn chỉnh một ứng dụng Expense Tracker có khả năng theo dõi thu chi, phân loại danh mục, vẽ biểu đồ phân tích xu hướng dòng tiền và xuất báo cáo CSV.

Quan trọng hơn cả tính năng nghiệp vụ, trọng tâm của môn học Triển khai và Quản trị Hệ thống Phần mềm là quy trình đóng gói, điều phối container hóa, bảo mật gateway, giám sát số liệu hiệu năng và tập trung hóa nhật ký lỗi theo tiêu chuẩn DevOps chuẩn công nghiệp.

2.2. Phân vùng mạng và cô lập dịch vụ (Network Isolation)

Để đảm bảo nguyên tắc an toàn thông tin cao nhất, dự án thiết lập 3 mạng Docker Bridge độc lập:

  • frontend_net: Vùng mạng biên chỉ chứa nginx, app và pgadmin. Phục vụ việc nhận request từ client và chuyển tiếp vào ứng dụng.
  • backend_net: Vùng mạng nội bộ tuyệt mật chỉ chứa app, postgres, pgadmin và postgres-exporter. Tuyệt đối không có Nginx và Internet truy cập trực tiếp vào đây.
  • monitoring_net: Vùng mạng chuyên dụng cho lưu lượng đo lường và nhật ký: prometheus, grafana, loki, promtail, cadvisor, postgres-exporter, nginx-exporter. Tách biệt hoàn toàn khỏi băng thông của người dùng.

CHƯƠNG 3: TRIỂN KHAI CHI TIẾT ỨNG DỤNG, DATABASE VÀ NGINX

3.1. Triển khai Ứng dụng Web Expense Tracker

Ứng dụng được viết bằng Node.js 20 (Express Framework) kết hợp thư viện prom-client và giao diện người dùng responsive tích hợp Chart.js. Mã nguồn được tổ chức module hóa cao:

  • app/src/db.js: Quản lý Connection Pool kết nối PostgreSQL với cơ chế thử lại (Retry Backoff) lên đến 15 lần, đảm bảo ứng dụng không bị crash khi container database đang trong quá trình khởi động.
  • app/src/metrics.js: Khởi tạo các Prometheus Gauges tùy chỉnh: expense_tracker_total_transactions, expense_tracker_total_income, expense_tracker_total_expense, expense_tracker_net_balance và các Histograms đo lường thời gian phản hồi API.
  • app/src/server.js: Cung cấp các API RESTful: /api/transactions (CRUD giao dịch), /api/categories (danh mục), /api/stats (thống kê biểu đồ), /api/export-csv (xuất tệp CSV) và /metrics (Prometheus scrape endpoint).

3.2. Thiết kế Cơ sở Dữ liệu PostgreSQL & pgAdmin 4

Cơ sở dữ liệu expense_db gồm hai bảng liên kết khóa ngoại với các chỉ mục tăng tốc tra cứu:

CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    type VARCHAR(20) NOT NULL CHECK (type IN ('income', 'expense')),
    icon VARCHAR(50) DEFAULT 'tag',
    color VARCHAR(20) DEFAULT '#4f46e5'
);

CREATE TABLE transactions (
    id SERIAL PRIMARY KEY,
    amount NUMERIC(15, 2) NOT NULL CHECK (amount > 0),
    type VARCHAR(20) NOT NULL CHECK (type IN ('income', 'expense')),
    category_id INT NOT NULL REFERENCES categories(id) ON DELETE RESTRICT,
    transaction_date DATE NOT NULL DEFAULT CURRENT_DATE,
    description TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_transactions_date ON transactions(transaction_date);
CREATE INDEX idx_transactions_category ON transactions(category_id);

Tệp postgres/init/02-seed.sql tự động nạp sẵn 10 danh mục chi tiêu/thu nhập tiêu chuẩn và 20 giao dịch phân bổ qua các tháng, giúp biểu đồ trực quan hóa dữ liệu phong phú ngay từ lần khởi chạy đầu tiên.

3.3. Cấu hình Nginx Reverse Proxy, HTTPS Tự Ký & Security Headers

Nginx đóng vai trò là Web Gateway duy nhất của toàn bộ hệ sinh thái. Các tính năng kỹ thuật nổi bật bao gồm:

a. Chuyển hướng tự động HTTP sang HTTPS

server {
    listen 80;
    server_name localhost 127.0.0.1;
    location / {
        return 301 https://$host$request_uri;
    }
}

b. Thiết lập Chứng chỉ SSL tự ký chuẩn SAN (Subject Alternative Names)

Chứng chỉ RSA 2048-bit được sinh tự động bao gồm cả domain DNS:localhost và địa chỉ IP IP:127.0.0.1, kích hoạt các chuẩn bảo mật hiện đại TLSv1.2 và TLSv1.3.

c. Bộ 6 HTTP Security Headers phòng chống tấn công Web

# Bắt buộc trình duyệt chỉ dùng kết nối an toàn HTTPS trong 1 năm
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

# Chống tấn công MIME-sniffing
add_header X-Content-Type-Options "nosniff" always;

# Chống tấn công Clickjacking (ngăn chặn nhúng iframe trái phép)
add_header X-Frame-Options "SAMEORIGIN" always;

# Kích hoạt bộ lọc chống Cross-Site Scripting (XSS)
add_header X-XSS-Protection "1; mode=block" always;

# Kiểm soát chặt chẽ thông tin rò rỉ qua Referrer Header
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# Chính sách nạp tài nguyên an toàn (CSP)
add_header Content-Security-Policy "default-src 'self' 'unsafe-inline' https://cdnjs.cloudflare.com https://cdn.jsdelivr.net; img-src 'self' data: https:; font-src 'self' https://cdnjs.cloudflare.com data:; connect-src 'self' ws: wss:;" always;

d. Định dạng Nhật ký Truy cập Chuẩn JSON cho Promtail

log_format json_analytics escape=json
  '{"timestamp":"$time_iso8601",'
  '"remote_addr":"$remote_addr",'
  '"request_method":"$request_method",'
  '"uri":"$uri",'
  '"status":$status,'
  '"body_bytes_sent":$body_bytes_sent,'
  '"request_time":$request_time,'
  '"http_user_agent":"$http_user_agent"}';

access_log /var/log/nginx/access_json.log json_analytics;

CHƯƠNG 4: HỆ THỐNG GIÁM SÁT PROMETHEUS & GRAFANA

4.1. Kiến trúc Thu thập Số liệu (Metrics Scrape Architecture)

Máy chủ Prometheus định kỳ kéo dữ liệu (Pull model) với chu kỳ 5 giây một lần từ 5 mục tiêu (targets):

  • expense-app:3000/metrics: Cung cấp các thông số nghiệp vụ tài chính và runtime Node.js.
  • postgres-exporter:9187/metrics: Cung cấp thông số kết nối, bộ đệm, số lượng transaction commit/rollback của PostgreSQL.
  • cadvisor:8080/metrics: Cung cấp số liệu tiêu thụ CPU, RAM, Disk I/O, Network I/O của tất cả các container.
  • nginx-exporter:9113/metrics: Cung cấp số lượng kết nối đang mở, số yêu cầu xử lý từ Nginx.
  • localhost:9090/metrics: Tự giám sát hiệu năng nội tại của chính Prometheus.
Kết quả kiểm tra thực tế: Cả 5 scrape targets trong Prometheus đều đạt trạng thái UP (100% Healthy) với độ trễ cạo số liệu cực thấp (dưới 30ms).

4.2. Thiết kế Bảng Điều Khiển Grafana (4 Phân Khu Giám Sát)

Grafana được tự động provisioning nạp sẵn bảng điều khiển "Expense Tracker - System & Performance Overview" gồm 4 phân khu chuyên biệt:

  1. Phân khu 1: Business & Web Application:
    • 4 thẻ Stat hiển thị: Tổng giao dịch, Tổng thu nhập (VND), Tổng chi tiêu (VND), Số dư ròng thời gian thực.
    • Biểu đồ đường biểu diễn HTTP Request Rate theo từng Endpoint: sum by (method, route) (rate(http_requests_total[1m])).
    • Biểu đồ đường phân tích độ trễ phản hồi phân vị 95 (p95 Latency): histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[1m])) by (le, route)).
  2. Phân khu 2: Container Resources (cAdvisor):
    • Biểu đồ % tiêu thụ CPU của từng container: sum(rate(container_cpu_usage_seconds_total[1m])) by (name) * 100.
    • Biểu đồ bộ nhớ RAM thực tế đang dùng (Working Set Bytes): sum(container_memory_working_set_bytes) by (name).
  3. Phân khu 3: PostgreSQL Database Performance:
    • Số kết nối hoạt động: pg_stat_activity_count.
    • Tỷ lệ Cache Hit Ratio (thực tế đạt 99.4%): sum(pg_stat_database_blks_hit) / (sum(pg_stat_database_blks_hit) + sum(pg_stat_database_blks_read)) * 100.
    • Tốc độ Commit vs Rollback giao dịch: rate(pg_stat_database_xact_commit[1m]).
  4. Phân khu 4: Centralized Logs Stream (Loki):
    • Dòng log streaming trực tiếp kết hợp bộ lọc tìm kiếm theo thời gian thực.

CHƯƠNG 5: HỆ THỐNG NHẬT KÝ TẬP TRUNG LOKI + PROMTAIL & LOGQL

5.1. Cơ chế hoạt động của Loki và Promtail

Khác biệt với giải pháp ELK Stack truyền thống tiêu tốn nhiều tài nguyên do phải đánh chỉ mục toàn văn (full-text index), Loki chỉ lập chỉ mục các nhãn (labels) gắn kèm theo luồng log. Điều này giúp hệ thống hoạt động cực kỳ nhẹ nhàng, tiêu thụ ít hơn 80% RAM và đĩa cứng.

Promtail hoạt động như một log shipper thu gom các tệp log từ volume dùng chung: /var/log/nginx/access_json.log và /var/log/app/app.log. Bằng pipeline cấu hình bóc tách json, Promtail tự động trích xuất các thuộc tính như status, level, method, action thành các label để nạp vào Loki.

5.2. Các Kịch Bản Truy Vấn LogQL Thực Nghiệm Đạt Tiêu Chí Chấm Điểm

Kịch bản 1: Giám sát toàn bộ luồng log của ứng dụng Expense Tracker

{service="expense-app"}

Mục đích: Hiển thị toàn bộ nhật ký nghiệp vụ của ứng dụng, bao gồm cả log kết nối DB, log request API và log lỗi.

Kịch bản 2: Truy vết sự kiện người dùng tạo mới giao dịch tài chính

{service="expense-app"} |= "transaction_created"

Mục đích: Lọc chính xác các bản ghi log phát sinh khi người dùng thêm một khoản thu hoặc chi, hiển thị rõ số tiền, loại giao dịch và mã ID.

Kịch bản 3: Giám sát nhật ký truy cập Web Server Nginx

{job="nginx"}

Mục đích: Theo dõi toàn bộ các lượt truy cập đi qua cổng bảo mật Nginx với đầy đủ địa chỉ IP, phương thức HTTP và thời gian phản hồi.

Kịch bản 4: Phát hiện và cảnh báo các yêu cầu bị lỗi (HTTP Status >= 400)

{job="nginx"} | json | status >= 400

Mục đích: Bóc tách trường JSON status trong log Nginx để lọc ra các mã lỗi 4xx (Client Error) hoặc 5xx (Server Error), giúp quản trị viên phản ứng nhanh trước các cuộc tấn công quét cổng hoặc lỗi hệ thống.

Kịch bản 5: Đo lường tốc độ phát sinh log trên mỗi giây

rate({job="nginx"}[1m])

Mục đích: Vẽ biểu đồ trực quan tần suất ghi nhận request qua web server theo thời gian thực.

CHƯƠNG 6: HIỆN THỰC HÓA 5 BIỆN PHÁP HARDENING BẢO MẬT

Dự án đã áp dụng toàn diện 5 biện pháp gia cố an ninh (System Hardening) chuẩn bảo mật container của CIS (Center for Internet Security):

6.1. Biện pháp 1: Thực thi dưới quyền Non-Root (Non-Root Containers)

Chạy ứng dụng bằng quyền root trong container là một sai lầm bảo mật nghiêm trọng vì nếu xảy ra lỗi tràn bộ đệm hoặc Remote Code Execution, kẻ tấn công có thể thoát khỏi container và chiếm quyền điều khiển máy chủ Host. Trong dự án:

  • Tệp app/Dockerfile khởi tạo nhóm và user chuyên dụng: appgroup (GID: 10001) và appuser (UID: 10001), chuyển quyền hoàn toàn bằng chỉ thị USER 10001:10001.
  • Container prometheus chạy với user 65534:65534 (nobody).

6.2. Biện pháp 2: Phân vùng mạng và Che giấu cổng Database (Network Isolation)

Cơ sở dữ liệu PostgreSQL không hề mở bất kỳ cổng nào ra máy chủ Host (loại bỏ hoàn toàn thuộc tính ports: 5432:5432). PostgreSQL chỉ kết nối vào mạng nội bộ backend_net. Kẻ tấn công quét IP máy chủ từ bên ngoài Internet hoàn toàn không thể phát hiện hay kết nối trực tiếp đến cổng 5432.

6.3. Biện pháp 3: Nguyên tắc Đặc quyền Tối thiểu trên Database (Least Privilege)

Ứng dụng không sử dụng tài khoản quản trị tối cao postgres. Thay vào đó, ứng dụng kết nối qua tài khoản nghiệp vụ expense_user và chỉ được cấp quyền thao tác dữ liệu (DML):

GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO expense_user;
GRANT USAGE, SELECT, UPDATE ON ALL SEQUENCES IN SCHEMA public TO expense_user;

Người dùng này không có quyền DROP DATABASE, không có quyền ALTER TABLE và không có quyền SUPERUSER, triệt tiêu rủi ro bị phá hoại cấu trúc hệ thống nếu xảy ra lỗi SQL Injection.

6.4. Biện pháp 4: Giới hạn Tài nguyên (Resource Limits) & Cờ An toàn

Toàn bộ 11 dịch vụ trong docker-compose.yml đều được thiết lập giới hạn tiêu thụ tài nguyên phần cứng (ví dụ: app giới hạn 0.5 CPU, 256MB RAM; nginx giới hạn 0.25 CPU, 128MB RAM). Đồng thời toàn bộ dịch vụ đều được gán cờ:

security_opt: [no-new-privileges:true]

Cờ này vô hiệu hóa hoàn toàn khả năng tiến trình con nâng đặc quyền thông qua các nhị phân setuid/setgid.

6.5. Biện pháp 5: Bảo mật Biến môi trường & Ẩn thông tin Server

Mật khẩu mạnh được lưu trữ trong tệp .env (được đưa vào .gitignore không bị lộ lên GitHub), cung cấp tệp mẫu .env.example an toàn. Nginx cấu hình server_tokens off; để ẩn số phiên bản khỏi header phản hồi.

7.1. Hướng dẫn Quy trình Khởi động Hệ thống (One-command Run)

Để khởi chạy toàn bộ hệ thống từ đầu trên bất kỳ máy chủ nào có Docker, chỉ cần thực hiện 3 bước đơn giản:

docker compose up -d --build

7.2. Kết quả Kiểm thử Nghiệp vụ Ứng dụng

Khi mở trình duyệt truy cập https://localhost:

  • Giao diện tải nhanh, hiển thị 3 thẻ tài chính: Tổng số dư, Tổng thu, Tổng chi.
  • Biểu đồ Doughnut Chart thể hiện chính xác phân bổ chi tiêu của 10 danh mục.
  • Biểu đồ Bar Chart thể hiện chính xác xu hướng dòng tiền các tháng.
  • Thử nghiệm thêm giao dịch mới: Số dư và biểu đồ cập nhật lập tức mà không cần F5 toàn trang.
  • Thử nghiệm nút "Xuất CSV": Trình duyệt tải thành công tệp tin expense-report.csv chứa đầy đủ danh sách giao dịch.

7.3. Kết quả Kiểm thử Nginx HTTPS & Security Headers

Gửi lệnh kiểm tra tiêu đề phản hồi bằng curl:

curl -k -I https://localhost

HTTP/1.1 200 OK
Server: nginx
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
X-XSS-Protection: 1; mode=block
Content-Security-Policy: default-src 'self' ...

Kết quả chứng minh Nginx đã thực thi thành công việc chuyển hướng 301 từ cổng 80 sang cổng 443 và đính kèm đầy đủ các Security Headers theo đúng tiêu chí.
